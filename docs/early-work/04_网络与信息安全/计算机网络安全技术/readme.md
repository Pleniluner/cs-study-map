# 计算机网络安全技术

*依据本目录的 Packet Tracer 配置作业、身份认证分析、VPN/ACL 实验和历年题整理；目标是把密码机制、网络协议与安全策略落实到可验证的配置。*

---

## 📋 课程定位

本课程位于“网络原理”和“安全工程”之间：既要求理解加密、认证、访问控制、入侵检测等概念，也要求能在具体拓扑中配置地址、路由、口令、ACL、状态检测和站点间 VPN。

学习重点不是记忆命令，而是形成完整推理链：先描述资产、信任边界和允许的通信，再选择机制、确定部署位置，最后用正向与反向测试证明策略确实生效。

## 🎯 应掌握的知识

- **安全目标与模型**：机密性、完整性、认证、不可否认性、可用性，以及资产、威胁、攻击面和信任边界。
- **密码学基础**：古典密码、S-DES 教学模型、RSA、Diffie–Hellman、散列、MAC、数字签名和混合加密流程。
- **身份认证**：口令存储、挑战—响应、消息认证、证书与会话密钥；区分散列与真正的身份认证协议。
- **路由器安全基线**：IP/子网、静态路由与 RIP、控制台/特权/远程登录口令、配置文件保护和最小管理面暴露。
- **访问控制**：标准/扩展 ACL、通配掩码、入站/出站方向、规则次序、隐含拒绝和最小权限。
- **状态检测与防火墙**：静态包过滤和 CBAC 一类状态检测的差别，以及规则覆盖、返回流量和日志验证。
- **IPsec**：SA、SADB、AH/ESP、传输/隧道模式、IKE/密钥协商，以及认证与加密组合后的报文结构。
- **应用与系统安全**：TLS/SSL、电子邮件安全、恶意代码分类、异常/特征检测、蜜罐及安全监控的局限。

Packet Tracer 练习应放在密码与协议概念之后。只有先写出允许/拒绝矩阵，才能判断一串配置命令是在实现安全策略，还是偶然让测试通过。

## ⚙️ 配置实验方法

1. 画出拓扑、接口、子网、路由与信任边界，先建立完整连通性基线。
2. 将自然语言需求转成通信矩阵：源、目的、协议、方向、允许/拒绝和理由。
3. 每次只增加一种机制，并保存增加前后的配置与测试结果。
4. ACL 同时测试应允许、应拒绝、返回流量、规则边界和未明确列出的流量。
5. VPN 分别验证内网连通、明文公网不可达、SA 建立、加密流量计数和异常协商。
6. 报告中记录拓扑、配置位置、关键命令、测试矩阵、抓包/计数器证据和已知限制。

## 🔍 理论复习方法

- 对 S-DES、RSA 等计算题逐步保留中间值，特别检查初始/逆置换、模运算和密钥方向。
- 对 MAC、签名和加密组合题，标明谁持有什么密钥、每一步保护哪项安全属性。
- 对 IPsec 画出内外层 IP 头、AH/ESP、载荷和认证范围，再判断传输/隧道模式。
- 对 ACL/SADB 场景题写清匹配顺序、状态查找、异常输入与默认动作，不只写“丢弃”。
- 对防火墙、IDS、蜜罐和恶意代码题按“可见信息—检测依据—误报/漏报—处置”比较。
- 最后按主题拆解历年题，旧题只用于验证理解，不用于猜测当前范围。

## ⚠️ 归档与安全说明

- 资料来自较早年份，Packet Tracer、Cisco 命令和设备型号可能与当前环境不同；在工程副本或独立实验拓扑中复现。
- 作业中出现 DES、MD5、Telnet 和旧式口令保护，是历史教学环境的一部分，不应直接用于现代生产系统。
- 旧 README 记录了某一年开卷考试及易错点，只能作为复习经验；当前考试形式和范围必须以正式通知为准。
- 实验报告是完成样例，不能替代独立配置。直接复制配置往往会因接口、方向、地址或题目策略变化而失效。
- 抓包、认证测试和网络扫描仅限自有设备、课程提供环境或书面授权范围，不得针对真实第三方系统。

## ✅ 完成标准

完成本项目后，学生应能够：

1. 从业务需求画出网络拓扑、信任边界和允许/拒绝通信矩阵。
2. 解释加密、散列、MAC、签名和认证分别解决什么问题，不能解决什么问题。
3. 正确配置并验证路由器管理口令、ACL、状态检测和站点间 IPsec VPN。
4. 画出 TLS/IPsec/邮件安全等协议中密钥、消息和安全属性的关系。
5. 根据日志、计数器、抓包和正反测试定位一项安全策略失效的原因。
6. 比较防火墙、IDS 与蜜罐的可见范围、检测依据和局限。
7. 写出包含策略、配置、证据、异常情况和改进建议的可复现实验报告。
