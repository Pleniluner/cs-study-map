# 计算机网络专题训练

*依据本目录的虚拟拓扑演示、IPv4/IPv6、BGP 和 TCP 五组实验及学长资料整理；目标是把协议规范转化为可验证的状态机与报文处理代码。*

---

## 📋 课程定位

本课程是计算机网络原理的实现强化：不再只解释协议“做什么”，而是处理实际程序中的报文布局、网络字节序、校验、路由查找、状态迁移、定时事件和异常输入。

现存主线从虚拟网络环境开始，依次实现 IPv4 转发、IPv6 收发、BGP 状态机和简化 TCP。四个编程实验逐步增加状态和依赖，适合按“先无状态数据平面，后有状态控制协议”的顺序推进。

## 🎯 应掌握的知识

- 从拓扑、接口和地址表还原实验环境，区分主机、路由器、自治系统和互联网出口。
- 解析与构造 IPv4/IPv6 头部，处理长度、TTL/Hop Limit、校验、地址和网络字节序。
- 建立路由表并执行最长前缀匹配，正确区分本机接收、直接转发、下一跳转发和丢弃。
- 理解 IPv4 与 IPv6 在头部、广播、校验和扩展机制上的主要差异。
- 把协议规范转换为事件驱动有限状态机，维护状态、计时器和错误动作。
- 理解 BGP 的 Idle、Connect、Active、OpenSent、OpenConfirm、Established 状态及消息类型。
- 维护 TCP 连接控制块，处理连接建立/关闭、序号、确认、校验、发送与接收流程。
- 设计边界与异常测试，使用抓包、日志和逐事件回放验证协议实现。

## ⚙️ 实现实验方法

1. 从报告或接口定义提取输入、输出、错误类型和不可变量。
2. 为每种报文画位段布局，并为多字节字段标出主机/网络字节序转换位置。
3. 将纯函数先独立测试：校验和、地址比较、掩码长度、最长匹配和报文合法性。
4. 对状态协议写出事件—当前状态—动作—下一状态表，再实现分支。
5. 为每个阶段准备最小正常包、边界包、错误包、重复事件和超时事件。
6. 先验证单个模块，再在固定拓扑中做端到端测试；保留抓包与日志作为证据。
7. 报告中说明规范依据、数据结构、状态图、测试矩阵、失败案例和当前简化。

## 🔍 各实验检查重点

- **IPv4**：本机地址判断是否先于 TTL；找不到路由、TTL 耗尽和校验错误是否走正确丢弃路径。
- **IPv6**：固定 40 字节基本头、Payload Length、Next Header、Hop Limit 和 128 位地址是否正确处理；不要沿用 IPv4 广播假设。
- **BGP**：Open/KeepAlive/Notification/Update 在错误状态到达时的动作；ConnectRetry、Hold、KeepAlive 计时器是否一致。
- **TCP**：TCB 的四元组和状态、序号/确认号、伪首部校验、重复段、连接建立与正常/异常关闭。
- **通用**：结构体内存布局不能直接等同线上格式；长度、对齐、所有权和释放必须明确。

## ⚠️ 归档与环境说明

- 实验依赖历史教学框架及预定义接口，可能无法在现代编译器上直接运行；迁移时保留原接口语义，并在副本中修改。
- 实验 1 当前只有拓扑、录像和一则播放器说明，没有正式任务书或报告，因此 README 不推测其完整验收要求。
- 实验 5 是简化的客户端、停等式 TCP，不等同于完整生产 TCP；拥塞控制、乱序重组和多连接等能力可能未覆盖。
- 学长资料与当前主线来自不同年份，接口和实验方向可能不同，不应混合源码后直接构建。
- 现有代码是完成样例，可能包含协议简化或实现缺陷。应以报告任务、状态表和自己设计的测试交叉验证。

## ✅ 完成标准

完成本项目后，学生应能够：

1. 从拓扑与地址配置解释一个分组逐跳经过的节点和接口。
2. 独立解析、检查并构造 IPv4/IPv6 基本报文，正确处理字节序与长度。
3. 实现路由表和最长前缀匹配，覆盖本机、直连、下一跳、不可达和 TTL 异常。
4. 将 BGP 事件规范整理成完整状态表，并通过合法/非法事件序列验证实现。
5. 维护最小 TCP TCB，完成连接建立、数据收发、确认和连接关闭。
6. 使用抓包、日志、逐事件回放和自动化用例定位协议处理错误。
7. 清楚说明教学实现相对真实协议省略了哪些能力，以及这些简化带来的限制。
