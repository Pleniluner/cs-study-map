# 现代密码学

*依据本目录的古典密码分析、比特币专题、散列/分组密码实现、AES-GCM、RSA 实验和期末题整理；目标是从安全定义、数学结构贯通到算法实现与协议组合。*

---

## 📋 课程定位

密码学研究怎样在对手存在的环境中实现机密性、完整性、认证和不可否认性。本目录的材料跨度很大：从替换密码与 Enigma 的历史分析，到 DES/AES/SM4、SHA/SM3、RSA、Diffie–Hellman、数字签名及密码协议。

学习重点不是“写出一段能加解密的代码”，而是能说明安全目标、攻击模型、算法假设、密钥/随机数要求和组合方式，并用公开测试向量与负面用例验证实现。

## 🎯 应掌握的知识

- **数学基础**：模运算、最大公约数与扩展欧几里得、乘法逆元、快速模幂、素性测试、有限域和概率。
- **信息论基础**：熵、编码效率、Huffman 编码，以及密钥空间和统计信息对分析的影响。
- **古典密码**：移位、Playfair、仿射、Vigenère、Hill、置换密码和转子机；频率分析与重合指数。
- **分组密码**：Feistel/SPN 结构、S 盒、轮函数、密钥扩展，以及 DES、AES、SM4 的结构差异。
- **工作模式**：ECB、CBC、OFB、CTR 的传播、并行、填充与 IV/nonce 要求；认证加密和 AES-GCM。
- **散列与认证**：SHA-1/SHA-2/SHA-3、SM3、碰撞/原像安全性、MAC 与认证标签。
- **公钥密码**：RSA、ElGamal、Diffie–Hellman、混合加密、数字签名、挑战—响应和证书。
- **协议与应用**：密钥分发、中间人风险、PGP、X.509、区块链中的散列/签名/工作量证明及协议组合。

古典密码分析用于建立“模式泄漏”的直觉；现代密码必须继续学习严格的安全目标、随机性和组合方式。只掌握算法轮函数而忽略密钥、nonce、认证和错误处理，仍然无法构成安全系统。

## ⚙️ 编程实践主线

### 古典分析

先实现加解密，再实现字母频率、重合指数、密钥长度估计和候选评分。报告应区分自动推断、人工猜测和已知明文，并记录失败候选，而不是只展示最终明文。

### 现代原语

1. 用短消息和标准测试向量验证填充、端序、轮函数与最终输出。
2. 对散列保留每块/每轮中间状态，覆盖空消息、跨块边界和长消息。
3. 对分组密码先验证单块，再比较 CBC/OFB/CTR 的加解密、错误传播和并行行为。
4. 对 GCM 分别验证密文、附加数据和标签；标签失败时不得输出未认证明文。
5. 对 RSA 独立测试大数运算、素性测试、模逆、模幂、密钥生成和往返过程。

## 🔍 安全分析与验证

- 为每个原语写明输入、输出、密钥、IV/nonce、随机数和安全目标。
- 同时准备正确向量、单比特篡改、错误密钥、错误标签、边界长度和重复 nonce 等负面测试。
- 区分“算法实现正确”和“使用方式安全”：测试向量一致只证明部分功能正确。
- 组合协议时画出参与者、消息、密钥归属和攻击者能力，检查重放、降级、中间人和密钥替换。
- 对性能报告分别测量密钥生成、加密、解密、散列和 I/O，避免把文件读写混入算法吞吐。
- 对比多份实现时关注位宽、端序、填充和错误处理，不直接比较不可重复的单次时间。

## ⚠️ 归档与实现安全

- 资料主要来自 2015 年及更早教学环境，算法范围、接口和安全参数不能直接代表当前实践要求。
- DES、SHA-1、MD5 等出现在历史作业或课程衔接中，适合研究结构与攻击史，不应作为新系统的安全选型。
- 第四次作业中固定或全零的密钥/IV只适合作为可复现测试输入；真实系统必须按算法要求生成、唯一化并保护密钥和 nonce。
- 现有 C/C++ 代码是教学实现，未必具备常数时间、防侧信道、安全随机数、内存清理和完整错误处理，不应用于生产或保护真实数据。
- RSA 报告中的参数、安全性和性能评价属于历史作业观点，应通过当前课程要求和可靠实现重新验证。
- 压缩包、可执行文件与大体量密文是归档产物；优先审计源码，在隔离副本中构建，不直接运行来源不明的二进制。

## ✅ 完成标准

完成本项目后，学生应能够：

1. 完成模逆、有限域运算、熵、重合指数和 RSA/ElGamal 类书面推导。
2. 实现并分析至少两种古典密码，利用统计信息恢复密钥或明文。
3. 解释 Feistel 与 SPN、AES/DES/SM4，以及 ECB/CBC/OFB/CTR 的结构与权衡。
4. 实现一个散列函数和一种分组密码模式，并通过边界与标准向量验证。
5. 正确说明 MAC、数字签名和认证加密的安全目标及验证失败处理。
6. 实现或逐步推演 RSA 密钥生成、加解密和签名，说明数学假设与参数风险。
7. 画出 Diffie–Hellman、证书或 PGP 一类协议的消息与密钥流，并识别中间人/重放风险。
8. 明确区分教学代码、算法正确性和生产安全性，不将历史实现用于真实秘密。
