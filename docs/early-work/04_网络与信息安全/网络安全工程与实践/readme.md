# 网络安全工程与实践

*依据本目录的 ARP/IP 欺骗、中间人、IDS 逃逸和软件漏洞实验整理；目标是在明确授权的隔离环境中理解攻击面、采集证据、验证防护并完成负责任的安全报告。*

---

## 📋 课程定位

这是一门以实验为主的安全工程课程。现有材料覆盖链路/网络层信任、中间人风险、入侵检测边界和内存安全，要求学生把网络原理、操作系统、汇编与程序设计综合起来。

课程价值不在于“成功攻击一次”，而在于建立可复用的方法：界定授权范围，构造最小实验，记录正常基线，复现风险，解释根因，验证缓解措施，并确保环境可恢复。

## 🎯 应掌握的知识与能力

- **授权与伦理**：书面范围、目标、时间、允许动作、数据处理、停止条件和成果披露流程。
- **实验隔离**：虚拟机、内部网络、快照、固定地址、日志、受控靶机和可重复拓扑。
- **二三层信任**：ARP 缓存、子网掩码、网关、ICMP、IP/MAC 绑定及欺骗产生的非对称行为。
- **中间人风险**：流量转发、名称/地址解析、HTTP 明文暴露、TLS 证书验证和终端告警。
- **检测工程**：特征规则、流重组、协议规范化、误报/漏报，以及端点与 IDS 对同一流量解释不一致的问题。
- **内存安全**：栈帧、边界检查、控制流、动态链接与 return-to-libc 教学模型，以及 ASLR、DEP/NX、栈保护等缓解机制。
- **防护验证**：静态绑定/交换机防护、加密协议、网络分段、规则规范化、安全编译和代码修复。
- **证据与报告**：拓扑、抓包、日志、时间线、最小复现、影响、根因、修复和回归测试。

## ⚙️ 安全实验工作流

1. 写明授权目标、禁止目标、允许动作、数据保留和停止条件。
2. 使用离线或内部虚拟网络，给所有机器做快照并记录版本、地址和角色。
3. 先采集正常流量/程序行为，建立无攻击时的基线。
4. 只对课程靶机执行最小复现，避免扩大扫描、持久化或接触真实个人数据。
5. 同步保留发送端、检测点、目标端的抓包与日志，比较三方观察结果。
6. 实施至少一种缓解措施，再重复完全相同的测试证明风险被阻断。
7. 清理配置、恢复快照和敏感数据，最后提交影响、根因、修复与局限。

## 🔍 分实验复盘框架

| 层面 | 要回答的问题 | 防护方向 |
|---|---|---|
| ARP/IP | 哪个信任假设被破坏？两端观察为何不对称？ | 绑定、分段、交换机保护、监控 |
| 中间人 | 哪些数据是明文？客户端是否正确验证证书？ | 端到端加密、证书校验、安全告警 |
| IDS | IDS 与终端怎样重组同一数据流？ | 规范化、完整流跟踪、多层检测 |
| 内存漏洞 | 哪个边界缺失导致控制数据被覆盖？ | 长度检查、安全 API、编译/运行时保护 |

报告应同时给出成功证据和失败证据：例如未加防护时的行为、启用防护后的阻断、以及正常业务仍能工作的回归结果。

## ⚠️ 授权、归档与安全边界

- 所有欺骗、拦截、检测逃逸和漏洞利用仅限课程提供靶机、自有隔离设备或书面授权范围；本目录中的历史目标地址不应再次访问。
- 原 README 提到曾对校园网进行漏洞研究和在他人环境中尝试。该个人经历不构成当前授权，也不是可复制的实验方法。
- 报告中可能含历史脚本、地址、凭据片段或 flag。它们只作归档证据，不应传播、复用或用于真实系统。
- Python 2、旧版 Scapy/Snort、32 位目标和历史保护配置可能与当前环境不兼容；在无外网隔离副本中复现。
- 发现真实漏洞时停止扩大验证，保存最小证据，按课程/组织流程私下报告；不得公开可识别个人、凭据或未修复细节。

## ✅ 完成标准

完成本项目后，学生应能够：

1. 写出可执行的授权范围、实验拓扑、停止条件和数据处理方案。
2. 用抓包和日志解释 ARP/IP 信任、中间人位置及加密前后的可见信息。
3. 说明基于特征的 IDS 为何可能出现误报或漏报，并提出规范化和多层检测方案。
4. 从教学源码定位一类内存边界错误，解释控制流影响及至少三种缓解机制。
5. 为每个风险设计“未防护—启用防护—正常业务回归”的测试矩阵。
6. 在不接触真实第三方系统的前提下复现实验，并在结束后恢复与清理环境。
7. 写出包含影响、证据、根因、修复、回归结果和披露边界的专业报告。
