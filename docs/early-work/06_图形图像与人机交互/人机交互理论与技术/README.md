# 人机交互理论与技术

*依据本目录 2015、2016 两组作业、Fitts 实验数据、手势/眼动研究，以及 Leap Motion 与 StarryVR 项目整理；目标是形成“理解用户—设计交互—制作原型—实验评价—迭代改进”的完整能力。*

---

## 📋 课程定位

人机交互关注人、任务、界面和使用环境之间的匹配。现有资料从 GUI/WIMP 历史、移动端菜单与图标、文字输入效率和 Fitts 定律出发，延伸到手势、眼动、VR/AR 和自然用户界面，并通过受控实验与两项 Unity 项目检验交互设计。

课程的核心不是把功能“做出来”，而是能说明为谁设计、解决什么任务、依据什么假设、如何测量效果，以及评价后怎样改。

## 🎯 应掌握的知识

- GUI、WIMP、移动交互、可穿戴设备和 NUI 的演进与适用边界。
- 用户、目标、任务、场景、约束和利益相关者的基本分析方法。
- 心智模型、可见性、反馈、一致性、映射、可发现性、错误预防与恢复。
- 菜单、图标、触控、键盘/输入法、手势、眼动和头部凝视的交互权衡。
- Fitts 定律中的距离、目标宽度、难度指数、移动时间和设备参数。
- 独立/因变量、控制变量、被试内设计、平衡顺序、试运行和疲劳控制。
- 正确率、完成时间、错误率、学习成本、满意度和眩晕等体验指标。
- 回归、方差分析、异常/错误点击处理，以及“统计显著”与设计意义的区别。
- 低/高保真原型、Unity 交互原型、设备 SDK 集成和迭代测试。
- 知情同意、最少采集、匿名化、隐私保护、无障碍和实验安全。

## ⚙️ 作业与实验主线

### 界面观察

选择一个真实任务，不只截图界面，还要记录用户目标、操作序列、每步反馈、失败路径和设备约束。比较桌面/手机/手表时应固定任务，再讨论菜单深度、目标尺寸、可发现性和输入方式。

### 定量实验

Fitts 或输入效率实验至少包含：

1. 明确假设、参与者标准、设备和任务。
2. 定义独立变量、水平、依赖变量和错误规则。
3. 使用被试内设计时平衡条件顺序，安排练习与休息。
4. 保留逐次原始数据，不只保存平均值。
5. 先处理错误/异常，再做回归或方差分析。
6. 报告效应、个体差异、限制和可转化的界面建议。

### 新型交互

手势、眼动和凝视应定义动作词汇、识别阈值、反馈、取消/恢复和误触处理。新颖并不等于更高效：需要与键盘、鼠标或触摸基线比较，并考虑疲劳、遮挡、隐私和可访问性。

## 🔍 大作业执行框架

| 阶段 | 关键问题 | 最小产出 |
|---|---|---|
| 问题定义 | 谁在什么情境下完成什么任务？ | 用户/场景、任务流、成功指标 |
| 方案探索 | 为什么选择此设备与交互？替代方案是什么？ | 草图、故事板、风险表 |
| 最小原型 | 最短端到端交互能否运行？ | 可重复演示和日志 |
| 试运行 | 用户理解手势/凝视吗？阈值合理吗？ | 问题清单和修订 |
| 正式评价 | 相对基线是否改善效果、效率或体验？ | 原始数据、观察、问卷 |
| 迭代 | 哪项证据对应哪项修改？ | 前后版本和决策记录 |
| 交付 | 他人能否复现并评价？ | 工程、说明、演示、报告 |

StarryVR 的头部凝视、3 秒停留与自动消失，以及打砖块项目的键盘/手势对照，都是可以复盘的设计决策；应进一步用用户数据验证阈值和交互自然性。

## ⚠️ 归档、伦理与环境说明

- 2015 与 2016 资料来自不同学生、年份和任务，不是同一套连续作业，也不代表当前课程要求。
- Fitts 目录包含多名参与者的逐次数据，作业中还出现设备和人口信息。再利用时应匿名化、限制访问，不把姓名或可识别信息写入新报告。
- 实验应取得参与者知情同意，允许中途退出，并减少疲劳、眩晕和重复动作风险。VR 测试出现不适时应立即停止。
- Unity、Oculus Rift DK2、Leap Motion 和 JMP 环境较旧；StarryVR 快照包含大量 Unity 生成文件，且可见自定义脚本很少，不能保证能按报告直接构建。
- 大作业报告展示的是一次设计与实现样例。原型功能、新颖度和主观评价不能替代系统的可用性实验。
- 论文和历史界面截图可能已过时；学习时关注研究问题和方法，不把当年产品现状当作当前事实。

## ✅ 完成标准

完成本项目后，学生应能够：

1. 为一个交互问题写出用户、场景、任务、约束和可量化成功指标。
2. 运用反馈、映射、一致性、可发现性和错误恢复原则评审界面。
3. 设计并分析 Fitts/输入效率实验，正确处理顺序效应、错误点击和个体差异。
4. 用回归、方差或描述统计把数据转化为有边界的设计结论。
5. 为手势、眼动或 VR 交互定义动作、阈值、反馈、取消与故障路径。
6. 完成一个端到端原型，并设置传统交互基线进行用户测试。
7. 根据测试证据迭代至少一轮，记录“问题—证据—修改—复测”。
8. 交付匿名、可复现、包含伦理与健康说明的工程和实验报告。
