### 资料使用原则

1. 先以题面、输入输出要求和约束为准，再阅读已有源码。
2. 源码是历史学习样本，不等同于标准答案；先独立设计，再比较实现。
3. 每读一个程序，都要回答四个问题：输入是什么、状态是什么、循环或递归保持什么、如何证明输出正确。
4. 修改练习时另存到自己的工作目录，保留本目录中的原始资料作为参照。

## ⚙️ C++ 核心知识体系

### 程序、类型与表达式

- 理解源文件、头文件、编译、链接和程序入口 `main` 的关系。
- 熟练使用 `bool`、`char`、整数和浮点类型，理解整除、取模、类型转换、运算符优先级与短路求值。
- 知道何时使用 `long long`：例如长度达到十万的字符串中统计有序字符对，结果可能超过 `int`。
- 能识别整数溢出、浮点比较和用 `sqrt` 判断边界时的风险。

### 控制流、函数与递归

- 用 `if`、`switch`、`for`、`while` 表达分类、枚举和模拟，并能写出循环不变量。
- 把输入、计算、输出拆成职责单一的函数，理解值传递、引用传递和指针传递。
- 为递归写清楚参数含义、终止条件、规模缩小方式和返回结果；递归快排与递归图形都应能够在纸上逐层展开。
- 区分局部变量、全局变量和静态存储期，避免依赖未初始化状态。

### 数组、字符串与动态结构

- 掌握一维和二维数组的下标范围、初始化、遍历顺序与空间消耗；能够在零下标和历史代码的一下标写法之间正确换算。
- 能使用 `std::string` 完成大小写转换、反转、计数、模式验证和分隔字段解析；阅读旧式字符数组时要检查容量与结尾 `\0`。
- 理解结构体和单链表节点，能够完成查找、插入、遍历与释放，并画出指针变化过程。
- 新代码优先使用 `std::vector`、`std::array`、`std::string` 和 RAII，减少固定缓冲区、裸指针与手工资源管理。

### 输入输出与错误处理

- 熟练使用标准输入输出和文件流，正确处理空白、换行、文件结尾及格式错误。
- 能按题目要求解析成绩文件、魔方六个面和配置项，并在文件打不开、字符非法或数量不符时给出明确失败结果。
- 输出必须严格符合格式；调试信息不能混入评测输出。

## 🔍 算法与题型主线

| 主线 | 材料中的代表任务 | 学生必须掌握 |
| --- | --- | --- |
| 枚举与逻辑 | 五个真假变量、数字等式、嫌疑人和角色推理 | 定义状态空间，完整遍历，用布尔表达式验证约束 |
| 模拟与矩阵 | 星号图形、螺旋矩阵、开关灯、日期与星期、烹饪流程 | 明确状态、事件顺序和边界，避免重复或漏处理 |
| 数学与数论 | 素数、最近素数、回文素数、友爱数、连续整数和、三进制盒子 | 试除与筛法、因子枚举、公式推导、整型范围 |
| 字符串与解析 | IP 区间、大小写操作、区间压缩、替换密码、后缀排序 | 字符分类、分隔符解析、频次统计、比较规则与格式校验 |
| 递归与分治 | 递归方框、快速排序、归并排序及中间过程 | 递归契约、分区或合并不变量、终止性和复杂度 |
| 递推与动态规划 | 错排、数塔最大路径、快速倍增斐波那契 | 状态定义、转移、初值、计算顺序与空间优化 |
| 搜索与回溯 | 质数相邻网格、最大权二分匹配、角色分配、魔方局部状态搜索 | 候选生成、剪枝、撤销状态、访问判重与失败条件 |
| 文件与数据处理 | 成绩文件、数字文件和不及格名单 | 文件协议、逐条解析、累计统计和稳定输出 |

算法选择必须由约束驱动：

- 数据量约十万时，优先寻找线性或 `O(n log n)` 方法；字符串有序对可边扫描边累计，不能枚举全部位置对。
- 字符串长度不超过一百时，可以先写清楚后缀比较规则，再考虑是否需要更复杂的后缀数组算法。
- `n <= 13` 的匹配或角色题允许指数级搜索，但仍应利用位掩码、上界和剪枝控制分支。
- 数塔问题应从指数级递归转成自底向上的动态规划；排序问题要能解释 `O(n²)` 与平均 `O(n log n)` 的差别。
- 所有复杂算法都先写出最小正确版本，再用测试和复杂度分析指导优化，不能用硬编码答案代替算法。

## 📦 魔方综合项目

魔方大作业是本课程的能力汇合点。它同时要求精确的数据表示、可靠的旋转操作、搜索或公式策略、文件处理和结果验证。建议按“接口层—状态层—求解层—验证层”拆开实现。

### 外部格式与内部状态

- 根据作业要求读取六行，每行九个字符，颜色来自 `R`、`B`、`Y`、`G`、`O`、`W`；明确六个面的输入顺序。
- 校验每种颜色恰有九个、中心块符合固定面色，并理解红—橙、蓝—绿、黄—白的对面关系。
- 外部面序与源码中的 `UFRDBL` 内部编号不是同一概念，必须在唯一的转换层中完成映射，不能让映射规则散落各处。
- 可选择“六个 3×3 面”或“54 个贴纸”表示状态；无论采用哪一种，都要记录每个面的朝向约定。
- 颜色数量正确不代表物理上一定可还原。边块翻转、角块扭转和排列奇偶性属于进阶合法性检查。

### 旋转引擎

- 独立实现六个面的顺时针与逆时针旋转；若内部支持 `U2`、`y` 等扩展动作，应在输出前规范化为作业允许的命令。
- 每个动作同时更新本面九格和相邻四条边，最好用置换表统一描述，避免为每个方向复制大量赋值代码。
- 必须通过性质测试：动作接逆动作回到原状态，同一面转四次回到原状态，半转两次回到原状态，所有动作保持颜色计数不变。

### 求解器结构

[现有求解源码](hw/rubik/solve.cpp)采用分层还原框架：先处理第一层十字和角块，再处理第二层，最后完成顶层；其中包含限时状态搜索、固定公式、整体转向和答案化简。阅读时应重点理解以下思想：

1. 用目标判定函数衡量当前阶段是否完成，而不是只看整个魔方是否复原。
2. 搜索节点必须包含完整状态、上一步动作和父节点，才能判重并重建路径。
3. 避免连续旋转同一面造成无意义分支，并设置明确的深度、时间或节点上限。
4. 将整体转向产生的内部动作映射回固定观察方向，再合并连续同面动作。
5. 输出答案后，从原始状态重新执行整段动作；只有回放确实得到完成状态，结果才算有效。

求解策略不必拘泥于现有实现。小规模阶段可用 BFS 或迭代加深，完整求解可研究 IDA*、模式数据库或两阶段方法；无论选哪一种，都要说明状态规模、启发信息、剪枝规则和失败行为。

## 👥 结对编程与工程习惯

结对任务要求两人共同思考、共同承担代码，而不是把题目切成互不相干的两半。

- **驾驶员**负责把当前共同方案写成代码；**领航员**实时检查边界、变量含义、算法不变量和测试。
- 开始编码前先在纸上模拟最小样例；完成一个小步骤就运行测试，并频繁交换角色。
- 两人都应能解释全部代码、复现错误和说明取舍，提交物不应存在“只有一个人懂”的模块。

快速排序任务尤其要掌握：

1. 为 `partition` 写出明确契约：处理哪个闭区间或半开区间，返回值代表什么。
2. 证明每轮扫描都有进展，递归区间严格缩小，对全部相等的数据也能终止。
3. 测试空区间、单元素、双元素、已排序、逆序、重复值、负数和随机数组。
4. 用 `std::sort` 只作测试参照，不把它当作自己实现的一部分。
5. 不用随机扰动修改输入来规避重复值；分区逻辑本身必须正确处理相等元素。

工程上还应做到：启用较严格的编译警告，使用清晰命名，避免魔法数字，检查文件与下标，分离业务输出和调试输出，并让随机测试能够记录种子、重复复现。

## ⚠️ 历史代码阅读须知

本目录中的源码保留了当时的练习过程，适合找思路和复盘错误，但部分实现存在典型的初学者风险：

- 固定数组容量与实际下标不一致，或混用零下标和一下标，可能造成越界。
- 旧式字符数组依赖 ASCII 数值和 `\0`，缺少长度、字符类别与输入失败检查。
- `bits/stdc++.h`、`system("pause")`、混用 C 与 C++ 输入输出等写法可移植性较差。
- 直接硬编码回文素数表只能覆盖给定范围，无法代替生成、判定和复杂度分析。
- 快排示例使用固定容量、特殊哨兵和随机微扰，可能改变原数据或隐藏重复值问题。
- 链表示例创建节点后没有完整释放；魔方程序也有大规模全局数组、宏和限时随机过程，阅读与调试成本较高。
- 某些程序缺少文件打开检查、非法输入分支、稳定换行或确定性的失败输出。

推荐的阅读方式是：先恢复题目契约，再手算小例；随后为原程序构造反例，定位错误属于模型、边界、复杂度还是实现；最后用现代 C++ 独立重写，并保留测试作为证据。

- [ ] 能为排序、字符串和魔方操作设计正常、边界、反例与性质测试。
