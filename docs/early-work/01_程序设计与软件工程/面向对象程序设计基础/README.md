### 资料优先级

遇到题面、源码和报告不一致时，按以下顺序判断：

1. 题目说明、输入输出要求与约束
2. [学期 Q&A 知识清单](<../面向对象程序设计基础-姚海龙老师/hw/Semester Exercise/OOP_QA_List2017.docx>)中的概念要求
3. 教师提供的接口、框架和构建文件
4. 学生提交的源码与报告
5. 课堂展示和扩展阅读

学生源码是学习过程记录，不等同于标准答案。阅读时应先恢复题目契约，再判断实现是否正确、可移植和可维护。

## 🎯 学习目标

完成合并路线后，学生应具备以下可验证能力：

| 能力 | 完成标准 |
| --- | --- |
| 工具链 | 能解释预处理、编译、链接和运行，独立维护多文件项目、静态库与构建脚本 |
| 抽象与封装 | 能从需求中识别对象、职责、不变量和接口，并隐藏实现细节 |
| 对象生命周期 | 能解释构造、析构、复制、移动和赋值发生的时机，使用 RAII 管理资源 |
| 对象关系 | 能区分组合、聚合、借用和继承，正确处理名字隐藏、向上转型与对象切片 |
| 运行时多态 | 能设计抽象接口、虚函数层次和可替换实现，并通过基类引用或指针调用 |
| 可扩展设计 | 能依据变化点使用 Strategy、Template Method、Adapter、Factory、Observer 或 Command，而不是机械套模式 |
| 泛型编程 | 能编写函数模板、类模板和函数对象，理解迭代器与 STL 算法的协作方式 |
| 工程验证 | 能为模块设计测试、合法性检查和性能实验，并写出可复现的构建与使用说明 |
| 项目协作 | 能在个人或团队项目中交付 `src`、`testcase`、`doc`，并清楚说明自己的设计责任 |

这门课的最终目标不是“把所有功能塞进类里”，而是让数据、责任、资源所有权和变化边界都清楚。

## ⚙️ 必须掌握的核心知识

### 工具链与模块边界

- 理解预处理、编译、汇编、链接和装载各自处理什么问题
- 理解声明与定义、内部与外部链接、`extern`、头文件保护和 One Definition Rule
- 能编写支持增量构建的 Makefile，知道何时使用静态库、动态库和 CMake
- 头文件只暴露稳定接口，源文件保存实现；不要在公共头文件中随意使用 `using namespace`

### 类不变量与接口设计

- 为每个类写出职责、不变量、合法状态和失败行为，再决定成员变量与成员函数
- 默认保持数据私有，只开放维持不变量所必需的最小接口
- 正确使用构造函数初始化列表、默认参数、`explicit`、`const` 成员函数和静态成员
- 区分函数重载、名字隐藏、函数覆盖和模板实例化，能够解释编译器如何选择调用目标

### 生命周期与资源所有权

- 能准确预测默认构造、复制构造、移动构造、复制赋值、移动赋值和析构的调用顺序
- 理解浅复制为何会导致重复释放、悬空指针或共享可变状态，并能实现深复制或禁止复制
- 优先使用 `std::vector`、`std::string`、`std::unique_ptr` 和 `std::shared_ptr` 表达所有权，遵循 RAII 与 Rule of Zero
- 必须掌握 `new/delete` 与 `new[]/delete[]` 的配对，但新设计不应让裸指针承担不清晰的所有权

### 组合、继承与多态

- 组合表达 `has-a`，公有继承表达可替换的 `is-a`；私有继承不能只因“想复用代码”而随意使用
- 理解基类和成员对象的构造/析构顺序，多继承的歧义，以及对象切片的成因
- 通过基类引用或指针触发动态绑定；将覆写函数标记为 `override`，必要时用 `final` 封闭扩展点
- 多态基类通常需要虚析构函数；接口还应说明参数所有权、返回对象生命周期和异常保证

### 编译期多态与 STL

- 理解函数模板、类模板、默认模板参数、显式/隐式实例化和特化
- 理解模板定义通常位于头文件的原因，以及类型推导失败时如何定位问题
- 能正确设计 `operator=`、流运算符、前置/后置自增和函数对象，不制造意外隐式转换
- 能用迭代器、算法和函数对象表达通用遍历，并理解模板与虚函数分别适合哪些变化

### 刘老师试题检查点

[刘老师期中试题](../面向对象程序设计基础-刘知远老师/exam/2017OOP-期中考试_378502654.docx)应在完成对象关系和多态后集中练习。学生需要能够独立解释：

- 哪些声明会真正构造对象，指针数组为何不会构造所指对象
- 引用的初始化规则、对象成员可用类型和指针成员访问语法
- `const`、`static` 与 `this` 的关系，以及重载解析和名字隐藏
- 继承构造、虚调用、抽象类和纯虚函数的准确语义
- 编译器生成的特殊成员函数、复制消除关闭时的对象生命周期
- 转换构造函数、转换运算符、`explicit`、`static_cast` 与 `dynamic_cast`
- 函数模板、类模板、类型推导和返回值转换

要求不仅能选出答案，还能为每道代码阅读题画出对象时间线，并说明哪一条语言规则决定了输出。

## 🔍 作业与项目阶梯

这些作业中的算法不是旁支，而是面向对象设计的载体。学生既要保证算法正确，也要把算法封装为边界清楚的组件。

| 练习 | 算法或业务载体 | 面向对象与工程重点 | 建议产出 |
| --- | --- | --- | --- |
| 多项式/正项式 | 直接计算与秦九韶算法 | 命令行、多文件、接口声明、Makefile、非法输入 | 两种实现及计时对比 |
| Reviewer/Team Assigner | 随机分配与文件处理 | 类职责、文件流、状态封装、输出协议 | 可复现分配器与测试数据 |
| Graph/MST | Prim 或 Kruskal | `Graph` 与 `MST` 分工、数据表示、算法接口 | 随机点集、MST 与正确性检查 |
| Member/Matrix | 常量对象与矩阵乘法 | 默认构造、`const` 成员、文件构造、值语义 | 可安全复制的矩阵类 |
| Maze Router | BFS、回溯和最少转弯 | 基类复用、派生接口、库链接、算法替换 | 基础版与优化版路由器 |
| 资源复制纠错 | 动态字符数组 | 析构、复制构造、赋值、自赋值、数组释放 | 通过内存检查的值类型 |
| 软件剽窃检测 | KMP 与 Rabin–Karp | Strategy、Template Method、开放封闭、性能测量 | 可插拔匹配器与基准报告 |
| 期末 Problem 1 | Trie 前缀检索 | 抽象回调、继承、递归遍历、资源释放 | 可扩展 Trie 与自动测试 |
| 期末 Problem 2 | LCS 动态规划 | 模板、继承、数据转换、复杂度和内存 | 支持不同元素类型的 LCS |
| 个人项目 | Delaunay、MST、SAT、路径规划等 | 外部库、模块分层、配置、验证、可视化 | `src/testcase/doc` 完整包 |
| 团队项目 | 网络流、规则布线或其他研究题 | 抽象接口、多实现、智能指针、Adapter、CMake、协作 | 可复现实验和团队设计报告 |

现有团队项目实现把 `Route` 作为抽象接口，将网络流、规则算法和文件输入适配器放在不同实现中，并使用智能指针管理实例；同时提供命令行、测试数据、可视化和性能对比。它适合作为最后阶段的结构样本，而不适合在尚未掌握虚函数和所有权时直接照抄。

## 👥 工程实践与代码阅读

### 大型代码阅读方法

[代码阅读任务](<../面向对象程序设计基础-姚海龙老师/hw/Code reading report/Exercise-CodeReading/Exercise-CR-2017.pdf>)允许从 LiquidFun、Protobuf、Boost、TensorFlow 或 Caffe 中选择项目。正确顺序是：

1. 先成功构建并运行一个最小示例，记录环境与命令
2. 选择一个小子系统，不按文件名从头到尾通读整个仓库
3. 从入口或测试出发，追踪一条完整调用链
4. 画出模块结构、核心类关系和主要运行流程
5. 找出一个设计模式、一个资源管理策略和一个特有实现技巧
6. 用调试、日志、断点或小修改验证自己的理解
7. 在报告中区分“代码事实”“自己的推断”和“可以改进之处”

示例 LiquidFun 阅读报告完成了 Linux 构建、Testbed 生命周期、世界/物体/粒子定义和小块内存分配器分析，说明代码阅读不只是概述功能，还要进入一个具体机制。

### 项目交付标准

- `src`：源码、公开头文件、构建配置和必要依赖说明
- `testcase`：正常、边界、随机、非法和性能数据，附预期结果或验证器
- `doc`：问题定义、架构、类职责、算法、复杂度、使用方法、实验与局限
- 命令行：提供帮助信息、明确参数、稳定退出码和可复现的随机种子
- 正确性：实现独立验证器；路径项目至少检查连通、交叉、障碍和环
- 性能：同时报告数据规模、运行时间、解质量与运行环境，不能只展示最快一次
- 协作：每名成员都能构建、运行和解释全局结构，并明确记录个人贡献

[课堂展示目录](../面向对象程序设计基础-姚海龙老师/hw/inClassTalk/)可在核心路线完成后按需选读：Git、GDB、Make/CMake、Doxygen、UML 和内存泄漏属于通用工具；编译器优化、位运算、正则表达式属于语言扩展；Boost、LiquidFun、Caffe、TensorFlow 等属于库与领域探索。

## ⚠️ 归档阅读注意事项

这个资料库包含重复提交、后续修订、第三方源码和历史环境遗留，不能把目录顺序直接等同于学习顺序。

## ✅ 结课验收清单

- [ ] 能解释一个 C++ 程序从多个源文件到可执行文件的完整过程
- [ ] 能为一个类写出职责、不变量、公开接口和所有权说明
- [ ] 能准确跟踪构造、复制、移动、赋值和析构，并解释 Rule of Zero/Three/Five
- [ ] 能正确使用 `const`、引用、静态成员、重载、类型转换和异常安全接口
- [ ] 能区分组合、聚合、借用、公有继承和私有继承的语义

- [ ] 能从变化点出发选择 Strategy、Template Method、Adapter 或 Factory，并说明不用模式时的替代方案
- [ ] 能编写模板、函数对象和迭代器算法，并处理类型推导与模板定义位置
- [ ] 能将 MST、Maze、字符串匹配、Trie 或 LCS 中至少一个算法封装为可测试组件

- [ ] 能用刘老师期中题检验语言语义，而不是只记选择题答案
