## 🎯 掌握目标

- 熟练使用示波器、逻辑电平与波形发生功能；
- 测量 CMOS/TTL 门的传输特性和传播延迟；
- 把真值表、状态图转成可综合 VHDL；
- 正确使用 `entity/architecture/process/signal/component/port map`；
- 设计七段译码、加法器、计数器、分频器和有限状态机；
- 完成编译、仿真、时序观察、引脚分配和板级验证；
- 用测试向量覆盖正常、边界、复位和非法状态；
- 能解释资源、延迟、可读性和鲁棒性之间的取舍。

## ⚙️ 项目实践

每个项目至少保留以下产出：

1. 需求表和接口定义；
2. 真值表或状态图；
3. 模块化 VHDL 源码；
4. 独立测试平台与关键波形；
5. 综合后的资源/时序摘要；
6. 引脚表、板测步骤和观察结果；
7. 一个失败案例及定位过程。

建议改进旧源码：

- 优先使用 `ieee.numeric_std`，避免继续依赖非标准 `std_logic_arith/std_logic_unsigned`；
- 使用 `rising_edge(clk)` / `falling_edge(clk)` 表达时钟边沿；
- 避免无约束的 `integer` 状态，优先枚举类型；
- 为组合过程补全默认赋值，防止意外锁存器；
- 把分频、计数、译码和控制 FSM 拆成可测试模块；
- 明确异步/同步复位和有效电平。

## 🔍 验证与复盘

- 与非门的 `tPHL、tPLH、tpd` 如何从两路波形读取？
- 七段译码的段码极性改变时，源码应改哪一层？
- 串行进位与超前进位的关键路径分别是什么？
- 计数器在 `59 → 00`、暂停、复位同时出现时优先级如何定义？
- 密码锁错误三次、复位中途、管理员码错误时状态能否恢复？
- 仿真通过但板上失败时，时钟、复位、引脚、电平、抖动应如何排查？
- 是否为每个状态和边界值写了自检查断言？
- 能否从综合报告解释资源使用和最大频率？

## ⚠️ 资料边界与历史说明

- 352 个文件中多数为 Quartus 编译数据库和报告，真正应优先读的是 PDF、VHDL、QSF/QPF 和波形文件。
- 工程来自旧版 Quartus/CPLD 环境；器件、引脚和工具版本可能无法直接复现。
- 旧源码使用非标准算术包、`buffer` 端口和旧式边沿写法，适合学习思路，不代表现代最佳实践。
- 学生报告与代码可用于理解任务，不应直接复制为自己的实验提交。
