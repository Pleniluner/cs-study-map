# 操作系统

*本目录以 2017 年 uCore Lab 1–8 的完整工程快照为实践主线，并配有历年期中、期末题；学习目标是从启动代码一路构造进程、虚存、调度、同步和文件系统。*

---

## 📋 课程定位

操作系统是硬件与应用之间的资源管理层。本项目最有价值的部分不是记住若干定义，而是沿 uCore 的增量实验观察一个内核如何启动、建立地址空间、处理中断、运行进程并提供文件接口。

学习时要同时保持三种视角：

- **机制视角**：页表、上下文切换、系统调用和锁具体怎样工作。
- **策略视角**：页面置换、调度、分配和同步为何选择某种算法。
- **不变量视角**：哪些状态必须始终成立，何时改变，谁有权改变。

## 🎯 应掌握的知识

- x86 启动过程、实模式到保护模式、GDT、ELF 装载、链接脚本和内核入口。
- IDT、trapframe、中断与异常、特权级转换和系统调用路径。
- 物理页管理、PDE/PTE、虚实地址转换、页错误、换页和页面置换。
- 进程与内核线程的控制块、上下文、创建、阻塞、唤醒、退出与回收。
- Round-Robin、Stride 等调度策略，以及调度类接口和公平性指标。
- 信号量、条件变量、生产者—消费者、哲学家问题、死锁与并发不变量。
- VFS 与 SFS、inode、目录、文件描述符、读写路径、管道和链接。
- Make、GDB、QEMU、反汇编和日志驱动的内核调试方法。

建议先具备 C 语言指针与结构体、少量 x86 汇编、链表/树/队列、Makefile 和 Linux 命令行基础。

## ⚙️ 实验工作流

1. 先读当前 Lab 的报告与 Makefile，确认目标、入口和测试方式。
2. 画出关键数据结构及调用链，例如 page fault → do_pgfault → 建页表/换入。
3. 在干净副本中构建，记录工具链、QEMU 版本和完整命令。
4. 用小步修改和断言保持不变量；不要一次跨越多个子任务。
5. 先运行自动检查，再用 GDB 断点、寄存器、页表和日志解释执行过程。
6. 将当前 Lab 与前一 Lab 做有目标的源码比较，只观察本阶段新增机制。
7. 报告中写明设计、关键代码、测试、失败案例和局限，而不是只粘贴通过截图。

## 🔍 理论复习方法

历年题位于 [exam](exam)，其中有 [期中题](exam/期中) 和 [期末题](exam/期末)。建议按知识链复习：

- 对每个机制写出“触发条件—入口—状态变化—恢复路径”。
- 手算地址转换、页面置换、调度时间线和信号量值变化。
- 比较机制与策略，例如页表是机制，置换算法是策略。
- 能从一个竞态执行序列指出错误交错，并给出最小同步方案。
- 最后限时做历年题，并回到源码验证不确定的结论。

## ⚠️ 归档与环境说明

- 这些实验是历史 uCore/x86 教学环境，可能依赖 32 位工具链和特定 QEMU/GDB。建议先复制到隔离目录再构建，保留本归档不变。
- 各 Lab 目录包含 obj、bin、依赖文件等历史构建产物；不要据此判断当前环境已经构建成功。
- 八个目录是逐阶段快照，不宜把它们直接拼成一个工程。需要比较时，应以实验目标为边界进行差异分析。
- [历年题说明](exam/注.txt)提示题目并不完整且难度较高；它们只适合查漏补缺，不代表当前考核范围。
- 现有报告和实现属于学习样例。独立完成、自己调试和解释代码才是本项目的训练目标。

## ✅ 完成标准

完成本项目后，学生应能够：

1. 从复位/BIOS 开始解释内核启动、特权级、中断和系统调用路径。
2. 手工完成典型页表转换，并解释分配、缺页、换入换出和 TLB 相关行为。
3. 跟踪一个进程从创建到退出的生命周期及上下文切换现场。
4. 实现或分析一种页面置换、一种调度和一种同步方案，并说明正确性与代价。
5. 从系统调用跟踪到 VFS/SFS 的文件读写和可执行文件加载。
6. 使用 QEMU、GDB、反汇编和日志定位至少一类内核崩溃或状态错误。
7. 不依赖答案，画出关键机制的控制流和数据结构关系，并用测试证明自己的实现。
