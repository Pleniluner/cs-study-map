# 嵌入式系统

*当前目录只保留一则课程与 Project 经验，没有讲义、题目、源码或报告；以下 README 据此整理共同能力、项目方向和可执行的学习顺序，并明确区分归档信息与通用建议。*

## 📋 课程定位

归档记录把课程分为前半段学习、后半段 Project。已知项目大多围绕树莓派，横跨最小系统、供电与网络控制、性能测量、加速和人机交互。

嵌入式系统的共同主线是：在资源和接口受约束的硬件上，让软件可靠地感知、计算、通信和控制。无论选择哪个题目，都应完成“需求—硬件—软件—测试—演示”的闭环。

## 🎯 共同掌握目标

- 读懂处理器、内存、GPIO、串口、网络、存储和电源之间的系统边界。
- 配置嵌入式 Linux，理解启动、服务、权限、日志和资源限制。
- 完成开发机到目标板的构建、部署、远程调试和版本记录。
- 根据接口文档连接和驱动外设，处理电平、时序、异常与资源释放。
- 设计设备状态机、通信协议和失败恢复，而不是只完成一次性演示。
- 测量延迟、吞吐、CPU/内存、功耗或实时性，并说明测量误差。
- 把硬件接线、软件版本、复现步骤、测试结果和安全边界写入报告。

不同项目还需补充各自领域知识，例如实时调度、神经网络推理、人机交互或能源管理。

## ⚙️ Project 执行框架

### 需求与设计

先写清输入、输出、使用场景、资源约束和可量化验收条件。把硬件、系统服务、应用进程、网络端和用户界面画成方框图，标出数据流、电源流和故障点。

### 分阶段实现

1. 单独验证板卡启动、网络和远程登录。
2. 单独验证每个传感器、执行器或软件模块。
3. 做一条最短端到端链路，先不追求完整功能。
4. 加入超时、重试、掉线恢复、日志和安全状态。
5. 在空闲、满载、弱网络、重启和断电恢复等条件下测试。
6. 最后优化启动时间、资源、能耗、延迟或交互体验。

### 交付物

至少应有 BOM/接线图、环境与构建说明、源码、配置、启动方式、测试矩阵、原始测量、演示步骤、已知限制和安全说明。

## 🔍 分方向验证重点

- **监控系统**：重启自恢复、数据丢失、时间戳、存储上限和远程不可达。
- **供电与开关**：待机/峰值功耗、欠压、断网默认状态、控制鉴权和负载隔离。
- **神经网络加速**：模型精度不退化或退化可解释；区分预处理、推理和传输时间。
- **实时测试**：定义 deadline，报告分布和最坏值，而非只给平均延迟。
- **人机交互**：完成关键任务所需步骤、响应时间、错误反馈和可恢复性。

NBlot 的验证内容必须等待正式题目或原始资料确认。

## ⚠️ 归档经验与安全

- 原记录称前八周上课、后八周做 Project，且一次作业约耗时八小时；这是个人对某一学期的体验，不代表当前课程安排或工作量。
- 记录者选择太阳能供电/Wi-Fi 开关方向，并完成接线、烧录和 USB 线材处理。这可说明项目有实物集成环节，但不是通用操作步骤。
- 任何接线、焊接、剪线或改造都必须先断电，核对板卡电压、电流、极性和负载隔离；不熟悉市电时不得自行连接高压负载。
- 当前目录缺少正式题目、器件清单和历史工程，开始项目前必须补齐这些资料，不能仅凭本 README 采购或接线。
- 建议在独立工程中保存源码和实验记录，本归档目录只作课程索引。

## ✅ 完成标准

完成一个嵌入式项目后，学生应能够：

1. 给出系统方框图、接口/供电说明和可量化验收指标。
2. 从干净环境复现构建、部署、启动和远程调试流程。
3. 展示一条稳定的端到端数据或控制链路，并处理超时、重启和断连。
4. 针对项目目标测量实时性、性能、功耗或可用性，保留原始数据。
5. 用边界条件和故障注入证明系统不只在理想条件下工作。
6. 交付足以让他人复现的源码、配置、测试、演示和安全文档。
