# 并行计算机体系结构与编程

*依据本目录中的课程说明、四次书面作业和三次编程作业整理；目标是建立“算法—实现—硬件—性能”贯通的并行计算能力。*

---

## 📋 课程定位

这门课不只是学习某一种并行 API，而是训练如何把串行程序改造成适合现代处理器的高性能实现。目录中的课程说明显示，学习主线依次覆盖多核线程、SIMD/ISPC、CUDA GPU 和图计算，并通过书面题解释硬件为什么会产生相应的性能现象。

应始终用四个问题审视一个并行程序：

1. 工作如何划分，理论上可以同时执行多少？
2. 数据放在哪里，搬运成本是否超过计算成本？
3. 线程之间需要怎样的同步，是否会发生竞争或死锁？
4. 实测瓶颈来自算力、带宽、延迟、分支分歧还是负载不均？

## 🎯 应掌握的知识

- **并行性能模型**：加速比、并行效率、工作量与关键路径、Amdahl 定律、强扩展与弱扩展。
- **CPU 并行性**：指令级并行、超标量、流水线相关，多线程的任务划分、同步和负载均衡。
- **SIMD 与 ISPC**：向量宽度、程序实例、控制流分歧、向量利用率和数据布局。
- **GPU 执行模型**：线程、线程块、warp、共享内存、全局内存、占用率、延迟隐藏和访存合并。
- **并行原语**：归约、前缀和、直方图、原子操作、锁、屏障及生产者—消费者模式。
- **内存系统**：缓存一致性、内存一致性、memory fence、伪共享、局部性和算术强度。
- **图并行算法**：自顶向下、自底向上和混合 BFS，以及并行 PageRank 的同步与收敛。
- **性能工程**：建立串行基线、只改变一个变量、正确计时、验证结果、解释而不只报告数字。

## ⚙️ 三次编程作业主线

| 阶段 | 需要完成的能力 | 典型验证 |

| 图计算 | 实现 top-down、bottom-up、hybrid BFS 和并行 PageRank | 多种规模与稀疏度图；检查层级、收敛和性能转折点 |

## 🔍 学习与实验方法

每个程序都建议保留一张实验记录表：输入规模、线程或 block 配置、运行时间、加速比、验证结果、主要瓶颈和下一步假设。至少完成以下对照：

- 串行与并行版本使用完全相同的输入，并先比较输出。
- 预热后多次计时，报告中位数或稳定区间，避免只取最好的一次。
- 分离初始化、数据传输与核心计算时间。
- 对线程数、任务粒度、block 大小或数据规模做参数扫描。
- 用硬件资源和访存行为解释曲线，不把“更快”本身当作结论。

## ✅ 完成标准

完成本项目后，学生应能够：

1. 为一个串行程序识别可并行部分、依赖、同步点和潜在瓶颈。
2. 分别用 CPU 线程、SIMD 或 GPU 表达合适的并行结构，并说明选择依据。
3. 正确使用 scan、归约、原子操作、锁和屏障，并识别数据竞争、死锁与伪共享。
4. 根据利用率、分歧、带宽、局部性和负载均衡解释性能结果。
5. 独立完成 BFS/PageRank 一类不规则并行算法的正确性与性能验证。
6. 写出包含基线、变量控制、数据、图表和原因分析的可复现实验报告。
