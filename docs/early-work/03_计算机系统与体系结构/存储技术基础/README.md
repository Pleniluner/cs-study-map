# 存储技术基础

*依据目录中的磁盘计算、I/O 基准测试、文件系统性能论文阅读和 Windows 文件虚拟化实验整理；主线是“度量存储—解释瓶颈—设计与验证系统”。*

---

## 📋 课程定位

存储系统的难点不在于记住某个设备速度，而在于区分延迟、吞吐、IOPS、利用率和缓存等因素，并用可复现实验判断瓶颈。现有资料从磁盘服务时间计算出发，延伸到 EXT4/IOzone 基准、FUSE 与内核文件系统比较，以及通过 API 拦截实现应用级文件虚拟化。

## 🎯 应掌握的知识

- **存储性能指标**：访问延迟、吞吐量、IOPS、队列深度、利用率和尾延迟的区别。
- **磁盘模型**：寻道、旋转等待、传输时间及它们对随机/顺序负载的影响。
- **容量与性能规划**：分别计算容量所需盘数和性能所需盘数，并取更严格的约束。
- **工作负载描述**：顺序/随机、读/写比例、文件大小、记录大小、并发度和工作集。
- **缓存效应**：页缓存、预热、写回和测试数据量对基准结果的干扰。
- **文件系统路径**：应用、系统调用、VFS、文件系统、块层和设备之间的关系。
- **用户态文件系统评估**：FUSE 与内核实现的开销来源、CPU 占用和实验公平性。
- **文件虚拟化**：动态库注入、Windows A/W API、路径映射、句柄语义和功能透明性。
- **实验与论文能力**：提出问题、控制变量、呈现数据、解释反常结果并评价研究限制。

## ⚙️ 两条实践主线

### 性能测量

1. 明确要回答的问题和指标，避免把带宽与 IOPS 混为一谈。
2. 描述设备、文件系统、挂载方式、缓存状态、工具版本和负载参数。
3. 让测试规模足以暴露目标层级，区分冷缓存、热缓存和写回影响。
4. 每组多次运行并保留原始结果；检查单位、异常值和稳定区间。
5. 用 I/O 路径、局部性、队列和缓存解释结果，不只罗列图表。

### 文件虚拟化

1. 先定义可观察语义：应用看到的路径、目录枚举、动态库和错误码应如何变化。
2. 建立统一路径规范化与映射函数，再覆盖 CreateFile、FindFirstFile、LoadLibrary 等入口。
3. 同时考虑 ANSI/Unicode 接口、相对路径、大小写、递归调用和资源释放。
4. 先做最小功能测试，再测兼容性和性能开销。
5. 将注入、hook、重定向、日志和恢复过程写入可复现实验记录。

## 🔍 结果分析框架

遇到性能差异时，依次排查：

| 层次 | 关键问题 |
|---|---|
| 应用 | 请求大小、访问模式和并发度是否一致？ |
| 系统调用/文件系统 | 是否有额外上下文切换、复制、日志或元数据操作？ |
| 缓存 | 数据是否命中页缓存？写是否只是进入缓存？ |
| 块层/设备 | 队列、寻道、带宽或介质是否成为瓶颈？ |
| 测量方法 | 计时范围、预热、重复次数和统计方式是否公平？ |

论文阅读也使用同一框架：先还原研究问题与实验设计，再判断证据是否足以支持结论。

- submit 中的日志、dumpbin 输出和源码是一次提交的证据，不等于完整实验规范。
- 基准结果只对报告所描述的环境和参数有效。不要把历史数值直接当作当前硬件结论。
- API 拦截仅用于本地课程实验和自有程序，不应用于未授权软件或系统。

## ✅ 完成标准

完成本项目后，学生应能够：

1. 用一致单位计算服务时间、吞吐、IOPS、利用率及容量/性能配盘需求。
2. 为一个存储问题设计包含基线、变量控制、重复测量和缓存处理的基准。
3. 根据工作负载和 I/O 路径解释顺序/随机、读/写和不同记录大小的差异。
4. 说明用户态文件系统相对内核文件系统可能增加的开销，并评价实验是否公平。
5. 设计一个最小文件路径虚拟化层，列出必须覆盖的接口、边界条件和测试。
6. 写出可复现的实验或论文阅读报告，明确结论、证据、假设和局限。
