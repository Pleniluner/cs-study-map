# 计算机系统结构

*依据本目录的书面作业、Cache 替换实验、Tomasulo 模拟器和历年题整理；重点是用定量方法理解处理器、存储层次和并行执行的设计权衡。*

---

## 📋 课程定位

本课程关注“怎样组织计算机才能获得更好的性能、成本与可扩展性”。它与计算机组成原理相邻，但重心不同：组成原理更偏向部件及 CPU 的具体构造，系统结构更强调性能方程、流水与指令级并行、Cache/一致性、向量处理和互连网络等架构权衡。

学习任何结构时，都应能回答：它解决什么瓶颈、增加哪些硬件状态、怎样保证正确、在何种工作负载下有效，以及代价是什么。

## 🎯 应掌握的知识

- CPU 时间、CPI、时钟周期和指令数之间的关系；加速比与 Amdahl 定律。
- 指令系统与编码的基本权衡，包括操作码扩展和程序的内存表示。
- Cache 地址划分、直接/组相联映射、替换算法、写策略、缺失分类与 AMAT。
- 流水线吞吐、加速比、效率、结构/数据/控制相关、旁路、停顿和调度。
- 预约表、禁止表、冲突向量和状态转换等流水线调度分析。
- Tomasulo 的保留站、寄存器重命名、公共数据总线、动态调度与精确状态问题。
- 向量处理器的 convoy、chaining、strip mining 和启动开销。
- 多核缓存一致性、MSI/MESI、伪共享、内存带宽及一致性流量。
- 互连网络的连接函数、直径、带宽、路由和扩展性。

## ⚙️ 两个实验项目

### Cache 替换策略

先实现一个明确的基线策略，再增加新策略。每个策略都应说明：

- 每条 cache line 或每组需要保存什么状态。
- 命中、填充和淘汰时怎样更新状态。
- 时间与空间复杂度，以及硬件实现成本。
- 在不同 trace 上 miss rate 为什么变化。
- 相对 LRU/Random 的收益是否稳定，是否存在反例。

目录中有两套实现与报告，可用于比较思路；不要把某一组 trace 上的胜负推广成普遍结论。

### Tomasulo 模拟器

模拟器应按周期推进，并能观察发射、执行、写回三个阶段。至少维护：

- 指令状态表、保留站、Load/Store buffer 和寄存器结果状态。
- 操作数的值或生产者标签，以及功能单元剩余周期。
- 公共数据总线广播和依赖唤醒。
- 结构冲突、RAW 相关和同周期事件的确定顺序。

验收时使用短指令序列逐周期手算，再与程序输出比较；尤其测试同一寄存器多次写、不同延迟运算和访存相关。

## 🔍 定量分析方法

1. 先写符号公式，再代数值；始终标注周期、秒、字节等单位。
2. 区分命中率与局部命中率、延迟与吞吐、单核性能与系统吞吐。
3. 画出时间线或状态表处理流水、Tomasulo 和一致性问题。
4. 明确基准机器、优化部分和未优化部分，再使用 Amdahl 定律。
5. 对一个设计同时陈述收益、硬件状态、关键路径、带宽和最坏情况。
6. 用实验 trace 验证策略，但保留至少一个反例或压力测试。

## ⚠️ 归档使用说明

- 实验目录中有压缩包、jar、截图和多个实现版本。先阅读实验要求，再选择一份源码在副本中构建，不要混合不同版本。
- JavaFX、浏览器脚本和编译器环境可能较旧；历史可执行文件不代表当前平台可直接运行。
- 参考答案与历年题属于不同年份，符号、假设和评分范围可能变化。先写清自己的假设，再核对答案。
- 目录中的报告是实现样例。应复现数据并独立解释，不要直接采用其中结论。

## ✅ 完成标准

完成本项目后，学生应能够：

1. 用 CPU 性能方程和 Amdahl 定律分析一个改进的上限与实际收益。
2. 完成 Cache 地址划分、AMAT、缺失率和写策略相关计算。
3. 为一段指令画出流水时间表，识别相关并给出旁路、停顿或调度方案。
4. 逐周期推演 Tomasulo，并实现可验证的最小模拟器。
5. 实现至少两种 Cache 替换策略，用多组 trace 比较正确性、miss rate 与状态开销。
6. 解释向量化、多核一致性和互连结构在性能与复杂度上的权衡。
7. 面对综合设计题时，从正确性、性能、成本和适用工作负载四方面论证答案。
