## 从十进制位权理解二进制

先区分一个数与它的写法。十二个物品的数量不会因为换一种记录方式而改变。十进制的 12 与二进制的 1100 可以表示同一个数量；进制改变的是符号的解释规则。本章没有特别标注的整数都按十进制读，二进制写法用 0b 开头，十六进制写法用 0x 开头。这些前缀是说明写法的标签，不是数值中的额外数位。

十进制使用 0 到 9 十种数字。从右向左，各位置的位权依次为 1、10、100，每左移一个位置，位权乘以 10。例如 307 = 3×100 + 0×10 + 7×1。中间的 0 虽然不贡献数量，却保留了位置，使 3 表示三个百而不是三个十。

二进制只使用 0 和 1。从右向左，位权依次为 1、2、4、8、16、32、64、128，每左移一个位置就乘以 2。例如 0b10110 = 1×16 + 0×8 + 1×4 + 1×2 + 0×1 = 22。这里共有五个二进制位，每个位上的数字决定是否计入相应位权。

反过来，把十进制 22 写成二进制，可以从不超过它的最大位权 16 开始。取走 16，剩 6；8 太大，不取；取走 4，剩 2；再取走 2，剩 0；最后的位权 1 不取。按照 16、8、4、2、1 的顺序记录取或不取，得到 10110。最后把取到的位权加回去，16 + 4 + 2 = 22，便完成反向检查。注意，不取的位置也要写 0，否则后续数字的位置就变了。

## 用十六进制缩短二进制写法

二进制适合明确描述每一位，但位数多时不容易阅读。十六进制使用十六个数字符号：0 到 9 表示零到九，A、B、C、D、E、F 分别表示十到十五。这里的字母是数字符号。例如 0x2F 的值是 2×16 + 15 = 47，而不是把十进制的 2 与 15 拼成 215。

十六进制从右向左的位权为 1、16、256、4096，每左移一个位置乘以 16。因为 16 = 2×2×2×2，四个二进制位正好覆盖十六种组合，从 0000 到 1111。因此一个十六进制位可以精确对应四个二进制位。例如 0xA6 中，A 的值为 10，对应 1010；6 对应 0110，所以整个写法对应 0b10100110。反向按二进制位权检查，128 + 32 + 4 + 2 = 166；按十六进制检查，10×16 + 6 = 166，两边相等。

把二进制转换成十六进制时，应从右端开始，每四位分成一组，最左侧不足四位时在左边补 0。例如 0b110101 分为 11 和 0101，补成 0011 和 0101，得到 0x35。它的值是 3×16 + 5 = 53，也等于 32 + 16 + 4 + 1。

对本章的非负整数，左侧补 0 不改变数值，因为新增位置的贡献都是 0；右侧补 0 则会改变原有数字的位权。0b101 是 5，0b0101 仍是 5，而 0b1010 是 10。之后为字节补足位数时，我们会反复用到这个区别。

## 数值、位数、字节与地址各是什么

本章采用以下教学模型：一个位只能取 0 或 1，一个字节恰好包含 8 位；内存按字节编址，每个地址指向一个字节。地址用十进制整数书写，相邻地址相差 1，表示相邻的字节位置。可以把内存画成一排小格，每格标一个地址，格内填写一个字节。地址是格子的标号，内容是格子里记录的数据，两者必须分开看。

一个字节的八个位权是 128、64、32、16、8、4、2、1。全部为 0 时数值为 0，全部为 1 时数值为 128 + 64 + 32 + 16 + 8 + 4 + 2 + 1 = 255，因此一个无符号字节能表示 0 到 255，共 256 个整数。两个十六进制位正好对应八个二进制位，所以我们常用 0x00 到 0xFF 描述一个字节。

接下来只讨论无符号 16 位整数。“无符号”表示不把任何位用于负号，十六个位都按非负位权计数。存储宽度固定为 16 位，即两个字节，允许的数值为 0 到 65535，共 65536 个。数值 5 可以写成 0b101，但在固定宽度的示意图中应写成 0000000000000101；它的数值没有改变，只是显示了全部存储位置。65536 则超出本章模型的允许范围，不能完整放进这两个字节。

例如地址 200 的内容为 0x05，含义是编号 200 的字节格记录了数值 5。200 既不是这个字节的数值，也不是它的位数。单看 0x05 的写法，还不能判断某项数据总共用了几个字节：宽度必须由问题条件另行指定。把数值的大小、写法的长度和实际存储宽度分开，是正确理解内存的基础。

## 小端序：低地址保存低有效字节

现在补充存取规则：每次在地址 a 存储一个无符号 16 位整数，使用地址 a 和 a + 1 两个字节，并采用小端序；加载时也从这两个地址按同一规则恢复整数。示意模型允许从任意有效地址开始，存储会覆盖这两个位置的旧内容。其他地址不参与本次操作。

任意允许的数值 N 都可以唯一拆成 N = H×256 + L，其中 H、L 都在 0 到 255 之间。把 N 除以 256，整数商就是 H，余数就是 L。我们称 H 为高有效字节，L 为低有效字节，因为 H 的一单位对整个数贡献 256，而 L 的一单位只贡献 1。“高”和“低”说的是对整个数的权重，并不是比较两个字节自身谁更大。

小端序规定：地址 a 保存 L，地址 a + 1 保存 H。例如数值 0x2479 中，H 为 0x24，L 为 0x79。在地址 300 开始存储后，地址 300 的内容是 0x79，地址 301 的内容是 0x24。恢复时得到 36×256 + 121 = 9216 + 121 = 9337，恰好也是 0x2479 的值。虽然低字节的数值 121 大于高字节的数值 36，二者的名称仍然不变。

书写一个多位数时通常把高位写在左边，而按地址递增查看小端内存时，会先看到低字节。因此内存中依次出现 79、24，并不意味着原数应写成 0x7924。小端序也不要求把每个字节内部的二进制数字倒过来：0x79 仍表示 01111001。它规定的是多字节数值在内存中的字节排列；实际机器如何解释某段内存，还需要数据宽度、类型和机器规则等信息。

## 跟着做：原创例题

### 例题 1

在本章无符号 16 位小端模型中，地址 400 和 401 的初始内容均为 0x00。把十进制整数 27437 存入地址 400 开始的两个字节。求它的四位十六进制写法、完整 16 位二进制写法和存储结果，并从内存反向验算。

1. 先检查范围：0 ≤ 27437 ≤ 65535，因此两个字节足够。
2. 按十六进制位权拆分：27437 = 6×4096 + 2861；2861 = 11×256 + 45；45 = 2×16 + 13。四个数字依次为 6、B、2、D，得到 0x6B2D。
3. 每个十六进制位转换成四个二进制位：6 对应 0110，B 对应 1011，2 对应 0010，D 对应 1101，因此得到 0110101100101101。
4. 拆字节：高字节 0x6B = 6×16 + 11 = 107；低字节 0x2D = 2×16 + 13 = 45。
5. 执行存储：地址 400 从 0x00 变为 0x2D，地址 401 从 0x00 变为 0x6B。
6. 从内存恢复：107×256 + 45 = 27392 + 45 = 27437。再按二进制中值为 1 的位验算：16384 + 8192 + 2048 + 512 + 256 + 32 + 8 + 4 + 1 = 27437。

**结果与核对**

十六进制为 0x6B2D，16 位二进制为 0110101100101101。按地址递增，两个字节依次为 0x2D、0x6B。从字节权重和二进制位权恢复的结果均为 27437，与原数一致。

### 例题 2

仍使用无符号 16 位小端模型。初始时地址 520 的内容为 0x36，地址 521 的内容为 0x92。先读取从地址 520 开始的整数，再仅把地址 520 改成 0x3E，地址 521 保持不变。求修改前后的十六进制、二进制及十进制数值，并核对变化量。

1. 低地址 520 提供低字节，高地址 521 提供高字节，因此初始整数为 0x9236。
2. 逐位转换：9、2、3、6 分别对应 1001、0010、0011、0110，初始 16 位二进制为 1001001000110110。
3. 高字节 0x92 = 9×16 + 2 = 146，低字节 0x36 = 3×16 + 6 = 54。因此初始值为 146×256 + 54 = 37376 + 54 = 37430。
4. 修改后低字节 0x3E = 3×16 + 14 = 62，高字节仍为 146。新整数为 0x923E，二进制为 1001001000111110。
5. 新值为 146×256 + 62 = 37438，变化量为 37438 - 37430 = 8。低字节的变化量也是 62 - 54 = 8。
6. 反向检查十六进制：9×4096 + 2×256 + 3×16 + 14 = 36864 + 512 + 48 + 14 = 37438。按新二进制验算：32768 + 4096 + 512 + 32 + 16 + 8 + 4 + 2 = 37438；旧写法缺少位权 8，故旧值为 37430。

**结果与核对**

修改前为 0x9236，即二进制 1001001000110110、十进制 37430；修改后为 0x923E，即二进制 1001001000111110、十进制 37438。只改变了低字节，整个数增加 8，三种写法的验算一致。

依次考察位权 128、64、32、16、8、4、2、1；再把八个位分成左右两组，每组四位。

<details>
<summary>解答与检查</summary>

181 取走 128 后剩 53，不能取 64；取走 32 后剩 21，取走 16 后剩 5；不能取 8，取走 4 后剩 1；不能取 2，最后取走 1。得到 10110101，分组为 1011 和 0101，十六进制为 0xB5。反向验算：128 + 32 + 16 + 4 + 1 = 181；11×16 + 5 = 181。

### 练习 2

在无符号 16 位小端模型中，地址 800、801 的初始内容分别为 0xAA、0xBB。现在从地址 800 开始存入十进制整数 1548。求两个地址的新内容，以及随后从地址 800 加载的结果。

<details>
<summary>提示</summary>

先用 1548 除以 256。存入整个 16 位整数会覆盖两个字节的旧内容。

</details>

<details>
<summary>解答与检查</summary>

1548 = 6×256 + 12，因此高字节为 0x06，低字节为 0x0C，整数的十六进制写法为 0x060C。小端存储后，地址 800 为 0x0C，地址 801 为 0x06。随后加载得到 6×256 + 12 = 1548。旧内容 0xAA、0xBB 已被覆盖，不参与计算。二进制写法为 0000011000001100，按位权检查为 1024 + 512 + 8 + 4 = 1548。

</details>

### 练习 3

在无符号 16 位小端模型中，地址 900、901、902 的初始内容依次为 0x10、0x20、0x30。先从地址 900 开始存储 0xABCD，再从地址 901 开始存储 0x1234。两次存储按顺序完成。求最终三个字节，并求最后从地址 900 开始加载的 16 位整数，用十六进制和十进制表示。

<details>
<summary>提示</summary>

每次存储都占两个相邻地址。第二次存储会覆盖第一次结果中的一个字节，应在每一步后重写地址与内容的对应关系。

</details>

<details>
<summary>解答与检查</summary>

第一次存储把低字节 0xCD 写到 900，把高字节 0xAB 写到 901，地址 902 仍为 0x30。第二次存储把 0x34 写到 901，把 0x12 写到 902。因此最终地址 900、901、902 依次为 0xCD、0x34、0x12。从 900 加载时只使用 900 和 901，得到 0x34CD。其值为 52×256 + 205 = 13312 + 205 = 13517。另按十六进制位权核对：3×4096 + 4×256 + 12×16 + 13 = 12288 + 1024 + 192 + 13 = 13517。

</details>

<a id="pitfalls"></a>

## 容易混淆的地方

- **认为二进制 100 比十进制 20 大，因为前者写了三位。** 比较前必须按各自的进制解释数位。0b100 = 4，所以小于十进制 20。写法的长度不能直接跨进制比较大小。
- **认为小端序就是把所有二进制位倒过来。** 本章的小端规则只安排两个字节的位置，每个字节的内容保持不变。0x2479 存储为低地址 0x79、高地址 0x24，其中 0x79 仍按 01111001 解释。
- **把低字节理解为两个字节中数值较小的那个。** 低字节指权重为 1 的部分，高字节指权重为 256 的部分。先写出 N = H×256 + L，再判定 H 和 L；不能按二者自身的大小排序。
- **认为一次存储过的两个字节会永久绑定，之后加载总能得到原数。** 加载使用的是当时各地址的内容。后续存储可能覆盖其中一个字节，所以应按时间顺序更新内存，再用最新的两个字节恢复数值。

## 本章边界

- 本章只处理非负、无符号且不超过指定宽度的整数，不讨论负数、浮点数、符号扩展或超出范围后的运算行为。
- 内存被简化成按字节编号的连续格子，并允许从任意有效地址存取；现实系统还涉及地址有效性、访问权限、对齐和存取指令。
- 小端序是本章明确指定的规则，并非所有机器和数据格式都使用同一种字节序；实际读取数据时还必须知道宽度与解释规则。
